# Projektanweisungen

Lies zuerst README.md und PROJECT.md. Dieses Repository ist die gemeinsame Arbeitsgrundlage für Codex, Claude und Antigravity.

- Ziel ist eine private, mobile Oberfläche für den vorhandenen Hermes Agent. Hermes bleibt die Quelle für Bots, Chats, Gruppen und Routinen.
- Orientiere dich an der Bedienidee von Grok Bot, erstelle aber eine eigene Gestaltung. Keine proprietären Assets oder Code kopieren.
- Nutze dokumentierte Hermes-Schnittstellen und die vorhandene Authentifizierung. Keine Zugangsdaten, Cookies, Tokens, persönliche Nachrichten, Bot-Exporte oder Serverkonfiguration in Git speichern.
- Der Server ist produktiv: bestehende Dienste, Daten, Konten, Routinen und Netzwerkregeln nicht überschreiben oder neu starten, solange laufende Arbeit beeinträchtigt werden könnte. Keine Routinen aktivieren oder Nachrichten versenden ohne konkreten Auftrag.
- Für parallele Arbeit pro Aufgabe einen eigenen Branch und möglichst einen eigenen Git-Worktree verwenden. Vor Änderungen `git status` prüfen; fremde uncommittete Änderungen nicht zurücksetzen. Änderungen und Tests im Abschlussbericht nennen.
- Funktionen ehrlich kennzeichnen: keine Demo-Daten als echte Daten ausgeben. Tests durchführen, die zur Änderung passen. Sicherheits- und Zugriffsannahmen dokumentieren.
- Nutzerseitige Freigaben und bestehende Anweisungen haben Vorrang vor Projektkonventionen.
